1. WHAT THIS IS

A command-line client on George's Android phone (Termux). It calls the OpenAI and Anthropic developer APIs with API keys. It does not use a subscription login.
Every reply must fit one strict four-field form. Local Python code checks the reply and strips filler before anything prints. A reply that fails the checks is never shown.

Repo: gugosf114/interaction-harness (private, GitHub).
Folder on the phone: /data/data/com.termux/files/home/interaction-harness
Shortcuts: "george" = Claude (claude-opus-5-5, high effort). "g1" = OpenAI (gpt-6.1-sol, high effort).


2. WHY IT EXISTS

George dictates by voice-to-text. He has chronic OCD. An unrequested hedge, caveat, apology or reassurance is a trigger: his attention locks on the stray line and the work stops.
His subscription work ran mostly in Claude Code and Codex inside Termux. There, every rule is a sentence in the prompt. Models follow it most of the time. For him, "most of the time" is the problem, because one stray line can cost a whole session.
The record behind this: 449 judged correction cases from 1,375 conversations. 201 repairs worked, 55 partial, 37 failed, 156 unclear. 24 of the 37 failures are repeats of the same few patterns. A new session does not carry the lesson, so he teaches it again.
The repeating patterns: unrequested hedges; saying work is done when it is not; answering the wrong task; ignoring context; folding or flipping a verdict under pushback; guessing at garbled voice input; treating a passing remark as an order to act.
The design answer: stop asking the model to behave. Put the checks in code, where they run every time.


3. HOW TO WORK WITH GEORGE

This matters more than the code. Most fights start here.
  - Clarify first. If his meaning is unclear, ask one short question before acting.
  - Answer first. Short sentences, small words, no greeting, no praise, no apology, no unrequested caveat.
  - Give a real verdict. Keep it when he pushes, unless he brings new evidence.
  - When he asks for work, do the work. Agreeing about the work is not doing it.
  - Say "I did" or "I did not." Never report work as done unless it ran and you saw the result.
  - Share ideas after the answer. He decides. An idea is not permission to act.
  - No background jobs. Foreground, one step at a time, visible.
His full rules live in /root/.claude/CLAUDE.md (Claude) and in the Codex AGENTS.md. Read them first.


4. HOW THE HARNESS WORKS

Context goes in four places, in this order:
  1. Frozen prefix. prefix_block.txt, version 3, 11,692 bytes, sent first on every call. Its SHA-256 is pinned in harness.py (starts 73d3ce09). A changed prefix stops the harness before any API call. Both providers cache it.
  2. Reply form. Four fields: intent, cleaned_input, direct_answer, execution_payload. OpenAI gets it as strict Structured Outputs. Claude gets it as the strict emit_reply tool with tool_choice "auto."
  3. Rolling history. The last 6 exchanges, capped at 24,000 characters. A command result follows its exchange as a separate JSON message typed execution_observation.
  4. The new request, after speech corrections, comes last.

What enforces what:
  - Code enforces: the four-field form; an observation can never carry a command; opening-line cleanup; the filler linter; the completed-work check; the control-character check; the y/N prompt before a command runs.
  - The completed-work check: a reply may report finished work only when an approved command that exited 0 directly precedes it.
  - The form fixes the boxes. It does not control the words inside direct_answer. The scrubber and linter remove filler.
  - The prompt only requests: tone, answer-first order, asking when input is unclear. Models follow this most of the time.
  - The API removes the consumer app's own system prompt. The model's trained habits stay. It can still hedge and refuse. A refusal is reported as a failure and never shown as an answer.
  - Claude can still answer in plain text because tool choice is "auto." The local gate rejects that reply.


5. COMMANDS

  george / g1                 open a chat; type "exit" to leave
  george "question"           one answer, then exit
  -c                          continue the last session
  --session NAME              open or create a named session
  -x                          ask y/N, then run the returned command
  --loop                      run approved commands and feed results back, up to 5 model turns (--max-turns 1 to 50)
  -y                          approve every command for this one run; only the operator can set it, the model cannot
  --recall "words"            search saved history, no API call
  -l                          dictate through Android speech recognition
  --no-normalize              send the typed words exactly

Old turns leave the model's view. --recall is a search George runs by hand. The model does not fetch old turns by itself.

8. HOW TO REBUILD

  1. Clone gugosf114/interaction-harness into the Termux home folder.
  2. Inside Debian (proot), make a Python environment named .venv in that folder and install requirements.lock.
  3. In a Termux shell, run the two key helpers and paste new keys:
       . "$HOME/interaction-harness/export-key.sh"
       . "$HOME/interaction-harness/export-anthropic-key.sh"
  4. Add the shortcuts to ~/.bashrc:
       alias george='/data/data/com.termux/files/home/interaction-harness/harness --engine anthropic --model claude-opus-5-5 --effort high'
       alias g1='/data/data/com.termux/files/home/interaction-harness/harness --engine openai --model gpt-6.1-sol --effort high'
  5. Run the unit tests listed in the README's Verification section.
Steps 1, 2 and 5 come from the repo files. Not re-run.
